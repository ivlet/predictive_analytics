# Лабораторная работа №2: виртуальный датчик для контроля процесса обжига в печи

## Состав проекта

- `lab2_virtual_sensor_kiln.ipynb` — Jupyter Notebook с полным пайплайном решения.
- `requirements.txt` — зависимости для запуска.
- `data/` — исходные CSV-файлы.
- `lab2_model_metrics.csv` — таблица метрик моделей, создается при запуске ноутбука.
- `lab2_predictions.csv` — прогнозы моделей на тестовых лабораторных замерах, создается при запуске ноутбука.

## Постановка задачи

Нужно построить виртуальный датчик для прогноза концентрации выходного продукта в печи обжига. Доступны минутные измерения телеметрии и нерегулярные лабораторные замеры target, которые поступают с задержкой примерно 10–15 минут.

В решении используется поправка на задержку: `sample_datetime = lab_datetime - 15 минут`. Затем лабораторные замеры синхронизируются с ближайшей доступной телеметрией в прошлом.

## Как запустить

```bash
python -m venv .venv
source .venv/bin/activate  # Windows: .venv\Scripts\activate
pip install -r requirements.txt
jupyter notebook
```

Откройте `lab2_virtual_sensor_kiln.ipynb` и выполните все ячейки сверху вниз.

## Основные этапы решения

1. EDA телеметрии и лабораторных замеров.
2. Синхронизация target и телеметрии с учетом задержки лабораторного анализа.
3. Feature engineering: лаги, скользящие средние/стандартные отклонения, признаки изменения.
4. Обучение моделей: Ridge, Random Forest, Gradient Boosting, SARIMAX + PCA.
5. Оценка качества: MAE, RMSE, MAPE, WAPE, Directional Accuracy, AIC/BIC для статистической модели.
6. Диагностика остатков и интерпретация важности признаков.

## Интерпретация результата

Предпочтительная модель выбирается по минимальному RMSE на тестовом периоде с учетом WAPE и Directional Accuracy. В базовом запуске ансамблевые модели на лаговых признаках дают более устойчивый результат, чем линейный baseline и статистическая SARIMAX-модель.

Для промышленного внедрения необходимо дополнительно проверить модель на новых временных периодах, настроить мониторинг дрейфа телеметрии и согласовать допустимый уровень ошибки с технологами.
